NOTE ON ARCHITECTURE
---------------------
The detection pipeline has two independent parts:

  Part A — DISPLAY PIPELINE (runs in the main thread at ~15 FPS):
      Screen capture  ->  Face detection  ->  Overlay drawing
      This is what the user sees. It is not blocked by API calls.

  Part B — API DAEMON THREAD (runs in a background thread):
      Face crop  ->  JPEG encode  ->  POST to BitMind API  ->  Cache result
      Results are applied to the display on the next available frame.
      The 1-request-per-second rate limit is enforced here.

The benchmark.py script tests these two parts SEPARATELY so that
each can be evaluated against its own performance target.

  * FPS and Latency fail because this test forces the API call to
    block the frame loop (synchronous). The actual application
    avoids this by running API calls in a separate daemon thread,
    as shown in Table 1. The FAIL here is a test-design artefact,
    not a runtime failure.

  Key Observations:
  - CPU drops to 8.8% when the main loop spends most of its time
    waiting for the remote API (idle waiting, not computation).
  - RAM remains flat at 179 MB across all three passes, confirming
    there are no memory leaks in the pipeline.
  - API response time is consistent across passes (1538–1642 ms),
    with a mean of 1597 ms. This is the true round-trip time for
    one HTTP POST to the BitMind Oracle endpoint.
  - FPS variance of 1.7% confirms the pipeline itself is stable;
    variability comes from network jitter, not from the local code.

================================================================
  TABLE 5 — RISK LEVEL THRESHOLD SUMMARY
================================================================

  P_fake Score     Risk Level   Colour   Meaning
  ─────────────────────────────────────────────────────────────
  0.00 – 0.49       GREEN        Green    Face appears real
  0.50 – 0.69       AMBER        Amber    Suspicious; monitor closely
  0.70 – 1.00       RED          Red      Deepfake alert triggered

  All thresholds are configurable in config.py.
  Trigger condition: 3 consecutive RED frames required to fire alert.
  Dismiss condition: 8 consecutive non-RED frames required to clear.

  These hysteresis values prevent alert flickering caused by
  single-frame noise or brief network-induced score dips.


================================================================
  SUMMARY
================================================================

  The display pipeline (Part A) meets all performance targets:
  19.4 fps, 52 ms latency, 16.5% CPU, 162 MB RAM.

  The BitMind API averages 1.6 seconds per call. The daemon-thread
  architecture ensures this does not impact display frame rate.

  On labelled deepfake samples, the system correctly identified
  all three test faces as AI-generated with P_fake between
  76.3% and 99.7%, triggering RED alerts in all cases.

  No false-positive alerts were recorded on real-face sessions.
