================================================================
  DEEPFAKE DETECTOR — FILE DESCRIPTIONS
================================================================

----------------------------------------------------------------
1. main.py
----------------------------------------------------------------
The application entry point. Creates the PyQt6 QApplication
instance, sets the application name and version, instantiates
the MainWindow, and starts the Qt event loop. This is the only
file that should be executed directly to launch the program.

----------------------------------------------------------------
2. config.py
----------------------------------------------------------------
Central configuration file that stores all tuneable constants
used across the entire project. This includes:
  - File paths (database location)
  - BitMind API endpoint URL and timeout settings
  - Rate limit delay between API requests, and the back-off used
    after an HTTP 429 response
  - MediaPipe face detection confidence threshold, the higher score
    a track needs before it counts as a face (FACE_ACCEPT_SCORE),
    detection working width (DETECTION_MAX_WIDTH), tiled detection
    settings (grid size, tile overlap, duplicate merging), and how
    many faces may await a verdict at once (MAX_PENDING_FACES)
  - Bounding box expansion ratio and alignment angle threshold
  - Face crop size and JPEG quality for API submission
  - Fake threshold (FAKE_THRESHOLD) for the binary REAL/DEEPFAKE
    decision, and verdict confirmation (CONFIRM_VERDICTS,
    CONFIRM_FAKE_VOTES)
  - Alert trigger and dismiss frame counters, and the alert cue
    switches (sound, desktop notification, evidence screenshot)
  - Low-light detection threshold and gamma correction exponent
  - Local explainability (CV heuristic) thresholds
No logic lives here — only constants. All other modules import
from this file, making tuning a one-place operation. FAKE_THRESHOLD
and the alert cue switches are overridden at startup by any values
saved from the Settings dialog (see dialogs.py).

----------------------------------------------------------------
3. runtime/capture/screen_capture.py
----------------------------------------------------------------
Handles real-time desktop screen capture using the mss library.
The ScreenCapture class initialises an mss capture context,
grabs frames from a configurable region of the screen (defaulting
to the full primary monitor), converts the raw BGRA output to
contiguous BGR numpy arrays (a sliced, non-contiguous view would
make every later OpenCV call copy the whole frame again), and
exposes start(), read(), set_region(), and
stop() methods. This module is the source of raw frames that feed
the detection pipeline.

----------------------------------------------------------------
4. runtime/detection/face_detector.py
----------------------------------------------------------------
Performs face detection and alignment on BGR frames using the
MediaPipe BlazeFace Tasks API. On first run it downloads the
BlazeFace short-range TFLite model. The FaceDetector class runs
detection on a copy of the frame downscaled to at most
DETECTION_MAX_WIDTH pixels wide, applying CLAHE contrast
enhancement to that copy when the frame is dark. It runs BlazeFace
on the full detection image plus a grid of overlapping tiles (so
small faces, e.g. in a meeting's gallery view, are not lost to the
model's 128x128 input) and merges duplicate detections across
tiles. Each detected box is mapped back to the full-resolution
frame, expanded by a configurable ratio, and cropped from the
full-resolution frame so the API sees native pixels; if the face
tilt exceeds a threshold, the crop is rotated upright about the
face's own centre. Returns a list of (crop, bbox, score) tuples
sorted most confident face first, with bbox in full-resolution
frame pixels and score the BlazeFace confidence, used by the
overlay renderer and inference engine.

----------------------------------------------------------------
5. runtime/detection/preprocessor.py
----------------------------------------------------------------
Converts a raw BGR face crop (numpy array) into JPEG-encoded
bytes ready for HTTP submission to the BitMind API. The
Preprocessor class resizes the crop to the configured square
size (FACE_CROP_SIZE) — area interpolation when shrinking, which
avoids aliasing artifacts, and cubic when enlarging — applies gamma
correction to brighten crops detected as low-light, and encodes
the result as JPEG at the configured quality (FACE_CROP_JPEG_QUALITY).
process_with_array() returns the JPEG bytes together with the
pre-encode BGR array (no JPEG round-trip) for local artifact
analysis in explainer.py,
and is also what Mini Mode displays as the face thumbnail. OpenCV
handles the BGR-to-YCbCr conversion internally, so the resulting
JPEG decodes correctly as RGB on the server side.

----------------------------------------------------------------
6. runtime/detection/inference.py
----------------------------------------------------------------
Submits JPEG face crop bytes to the BitMind Oracle API and
returns classification results. Key components:

  - FaceResult (dataclass): holds the raw P_fake score, risk
    level ("REAL" or "DEEPFAKE"), API response time in
    milliseconds, bounding box, last-updated timestamp, a list
    of local CV explanation strings (populated only for DEEPFAKE
    results), and the exact preprocessed thumbnail used for the
    analysis (for Mini mode display).

  - DeepfakeInferenceEngine: maintains a persistent requests
    Session with the Bearer token, enforces the 1 request/second
    rate limit on the free tier by spacing request start times
    (not the gap after each response), base64-encodes the JPEG payload,
    POSTs it to the API, and parses the isAI + confidence fields
    to derive P_fake. Failures are raised as typed errors: auth
    (401/403), rate limit (429, carrying any Retry-After value),
    transient (timeout, connection, 5xx), or other.

  - risk_level_for(): maps a P_fake score to REAL/DEEPFAKE using
    the current FAKE_THRESHOLD.

----------------------------------------------------------------
7. runtime/detection/explainer.py
----------------------------------------------------------------
Runs local CV forensic heuristics on a face crop already
classified as DEEPFAKE by the BitMind API, producing human-readable
evidence strings for the Detection Analysis card. No additional
ML model or pip dependency — numpy + opencv only. compute_metrics()
computes three signals: FFT high/low frequency energy ratio
(elevated ratio suggests GAN upsampling artifacts), inner-vs-border
noise-residual variance ratio (suggests the face was digitally
blended into the frame), and left-right symmetry deviation
(suggests artificially generated/warped features). analyze_artifacts()
compares each metric against a threshold from config.py and returns
0-3 evidence strings. Thresholds are calibrated as statistical
outlier cut-offs against a small manual sample, not a trained
classifier — treated as corroborating, best-effort evidence only.

----------------------------------------------------------------
8. runtime/threads/detection_worker.py
----------------------------------------------------------------
The core QThread that runs the real-time detection pipeline
continuously in the background. Architecture:

  - Main loop (~15 FPS): captures a screen frame, masks the app's
    own window region for display, optionally crops to a
    user-selected detection zone, runs face detection, assigns
    stable IDs to every detected face via _FaceTracker, treats a
    track as a face (drawn, counted and classified) only once one
    of its detections reaches FACE_ACCEPT_SCORE, queues crops of
    accepted faces that need (re-)classification — at most
    MAX_PENDING_FACES at once, most confident first; a classified
    face frees its slot for the next — and emits annotated frames,
    FaceResult lists, and pending bboxes to the GUI thread via Qt
    signals. Also emits a low-light warning based on a cheap
    downsampled brightness check and the detected face count.

  - API daemon thread: round-robins through all queued faces,
    JPEG-encoding each crop and calling the BitMind API once per
    face per cycle (rate limit is enforced inside
    DeepfakeInferenceEngine). A first REAL verdict is final; a
    first DEEPFAKE verdict keeps the face queued for more verdicts
    on fresh frames until CONFIRM_FAKE_VOTES of CONFIRM_VERDICTS
    agree, and the face's final score is the median of its
    verdicts. The local explainer runs on confirmed DEEPFAKE
    results. Results are cached and shared back to the main loop
    via a thread-safe lock; a classified face is locked until the
    user requests a manual re-check. Transient failures count
    towards a Degraded state; an HTTP 429 pauses requests (Retry-
    After, or a doubling back-off) without counting as a failure;
    a rejected API key stops the API thread and is reported via
    api_key_rejected.

  - _FaceTracker: assigns stable string IDs to faces across
    frames using bounding box centre proximity, ensuring that
    cached results remain consistent even when faces reorder or
    briefly disappear.

  - set_exclusion_region() / set_focus_region(): let the GUI
    blank the app's own window region and restrict detection to
    a user-drawn zone, respectively.

----------------------------------------------------------------
9. runtime/threads/alert_thread.py
----------------------------------------------------------------
A lightweight QThread that monitors the stream of FaceResult
lists produced by DetectionWorker and manages alert state.
Alerts are per face: it counts each face's consecutive DEEPFAKE
frames, and once a face reaches ALERT_TRIGGER_FRAMES it raises that
face's alert, once per session — even if another face's alert is
already showing or was acknowledged. Faces that alert on the same
frame are emitted together as alert_triggered(peaks, faces_on_screen)
so they share one evidence screenshot while each still gets its own
ALERT event. Once no face has been DEEPFAKE for ALERT_DISMISS_FRAMES
frames it emits alert_dismissed(). This hysteresis logic prevents
rapid flickering of the alert card in the GUI. Incoming result batches are queued non-blocking (frames are
dropped if the queue is full) to avoid stalling the GUI thread.

----------------------------------------------------------------
10. runtime/gui/main_window.py
----------------------------------------------------------------
The main PyQt6 application window. It wires all GUI components
and background threads together. Responsibilities include:

  - Building the full window layout: left panel (video + control
    bar), right panel (confidence gauge, Detection Analysis card,
    alert card, session info card, system log), session history
    table, and status bar. The status bar shows live indicators
    for the face model, the API key, and the database, plus the
    current threshold.
  - Starting and stopping DetectionWorker and AlertThread,
    connecting all Qt signals to their respective slots; a
    rejected API key stops the session with a clear message.
  - Updating the confidence gauge, FPS readout, face count,
    API response time, and session duration in real time.
  - Showing/hiding the alert card, syncing the always-visible
    Detection Analysis card with the latest result, and updating
    status indicators (Idle / Initializing / Detecting / Alert /
    Stopping).
  - Prompting the user to save or discard the session on stop.
  - Saving full-screen screenshots on demand, and automatically as
    evidence when an alert fires (if enabled in Settings).
  - Session history: exporting the selected session's events to
    CSV, deleting it, or clearing all history after confirmation.
  - Opening the Settings dialog.
  - Handling detection-zone selection events from VideoWidget and
    forwarding them to DetectionWorker.
  - Mini Mode: collapsing to a small always-on-top bar with live
    face thumbnails and Start/Stop controls, so a meeting window
    underneath stays visible; all other sections are hidden
    (not destroyed), preserving state when returning to full mode.
  - Pre-initialising the shared FaceDetector and
    DeepfakeInferenceEngine on a background thread at startup, and
    reusing them across sessions to avoid a slow per-session reload.
  - Using SetWindowDisplayAffinity, via window_affinity.py, to
    exclude the application window from mss screen capture,
    preventing the detector from analysing its own UI.

----------------------------------------------------------------
11. runtime/gui/video_widget.py
----------------------------------------------------------------
A custom QWidget subclass responsible for displaying live video
frames with face detection overlays. It keeps the latest BGR
numpy frame and, only when painting, scales it with OpenCV to fit
the widget (aspect ratio preserved) before converting it to a
QPixmap, so the full screen resolution is never converted in the
GUI thread. A QPainter-based paintEvent draws:
  - Colour-coded bounding boxes (green REAL / red DEEPFAKE)
    around analyzed faces, and dashed grey placeholder boxes with
    an "Analyzing..." badge for faces detected but not yet scored.
  - Confidence badges below each analyzed box showing the raw
    P_fake percentage, risk label, and a relative timestamp
    ("just now" / "Ns ago").
  - A blinking red circle with a "DETECTING" label in the
    top-left corner while a feed is active.
It also supports drag-to-select a rectangular detection zone
(left-click drag to set, right-click to clear), emitted via the
region_selected signal, and exposes has_frame so the main window's
screenshot action can tell whether a feed is active.

----------------------------------------------------------------
12. runtime/gui/gauge_widget.py
----------------------------------------------------------------
Custom-painted semicircular confidence gauge (GaugeWidget) used in
the Confidence Score card, replacing a plain horizontal progress
bar. Draws a background track plus a green -> amber -> red gradient
arc built from short interpolated segments, a marker dot at the
current value's position, 0%/100% end labels, and a centered
percentage + status label (e.g. "Real" / "Deepfake" / "—").
set_value(value, label) updates the reading (0-100) and label.

----------------------------------------------------------------
13. runtime/gui/face_thumbnail.py
----------------------------------------------------------------
Small bordered face-crop thumbnail widget (FaceThumbnail) used in
Mini Mode's live face strip, so the user can visually confirm which
specific face a confidence score belongs to without needing the
full video preview. set_face() displays the exact preprocessed BGR
crop that was analyzed (from FaceResult.thumbnail), with a
risk-coloured border (green/red) and a confidence percentage label;
clear() hides the slot when fewer faces are currently tracked than
the fixed thumbnail pool size (three, most suspicious first).

----------------------------------------------------------------
14. runtime/gui/session_log.py
----------------------------------------------------------------
A read-only QTextEdit subclass that displays a colour-coded,
timestamped log of all detection events within the current
session. Each event type has a distinct colour:
  - ALERT  → red
  - DISMISS → green
  - SESSION → grey
  - INFO    → light grey
  - ERROR   → orange
Entries are kept to a single line by design — the full DEEPFAKE
reasoning is surfaced continuously in the Detection Analysis card
instead. New entries are appended with HTML formatting and the
scroll position is automatically advanced to the latest entry.

----------------------------------------------------------------
15. runtime/gui/dialogs.py
----------------------------------------------------------------
Contains the SaveSessionDialog modal dialog shown when the user
presses Stop. It displays the session duration, number of alerts
triggered, and a colour-coded result badge ("Deepfake detected"
in red or "Clean" in green). The user can click Save (accepted)
to persist the session to the database, or Discard (rejected)
to drop it. The dialog result is checked in MainWindow._on_stop():
Save writes the stop event, Discard deletes every event logged
since the session's start event.

Also contains SettingsDialog, which edits FAKE_THRESHOLD and the
alert cue switches (beep, desktop notification, evidence
screenshot). Save applies the values to the config module at once
and persists them with QSettings; load_saved_settings() re-applies
them at startup, and "Reset to defaults" restores config.py's
values.

----------------------------------------------------------------
16. runtime/gui/alert_system.py
----------------------------------------------------------------
Provides notify_alert(), called when an alert fires so it is
noticed even while the meeting window has focus: it flashes the
app's taskbar entry and, unless disabled in Settings, plays the
system beep and sends a desktop toast notification via the plyer
library showing the peak P_fake confidence score. The toast runs on a daemon thread because
plyer's Windows backend blocks for the notification's duration,
and is wrapped in a try/except so that an unavailable
notification backend never crashes the application.

----------------------------------------------------------------
17. runtime/gui/window_affinity.py
----------------------------------------------------------------
Excludes the app's own window from screen capture at the OS
compositor level via the Windows SetWindowDisplayAffinity API —
WDA_EXCLUDEFROMCAPTURE on Windows 10 2004+ (build 19041+), or the
older WDA_MONITOR flag as a fallback on earlier builds — so the
app's window never reaches any capture buffer (ours or anyone
else's) in the first place. This is the primary self-exclusion
mechanism; DetectionWorker's pixel-masking (_mask_exclusion)
remains as a defensive fallback for non-Windows platforms or if
this call fails. No-ops on non-Windows platforms.

----------------------------------------------------------------
18. runtime/storage/database.py
----------------------------------------------------------------
Local SQLite persistence layer for session event logging. All
data is stored in a single file on the host machine (DB_PATH
from config.py) and is never transmitted externally. Key
functions:

  - log_event(): inserts a timestamped record with event type,
    detail text, and optional numeric fields (peak_confidence,
    breach_duration_sec, faces_detected, api_response_ms).
  - get_all_sessions(): reconstructs completed sessions from the
    event log by pairing "Detection started" and "Detection
    stopped" SESSION events in chronological order, counting
    ALERT events in between, and computing the duration — returns
    a list of summary dicts displayed in the history table.
  - is_available(): whether the database can be opened, for the
    status bar indicator.
  - get_session_events(): returns every event of one session,
    oldest first, for CSV export.
  - delete_session(): deletes all events belonging to a single
    session, identified by its start timestamp, used by the
    "Delete Selected" control in the history table.
  - clear_history(): deletes all records (used by the "Clear All"
    control).

----------------------------------------------------------------
19. detection_accuracy.py
----------------------------------------------------------------
Test script measuring detection accuracy on FaceForensics++ (c23):
the first ACCURACY_VIDEOS_PER_SUBSET videos of original (real) and
of the five manipulation methods in FF_FAKE_SUBSETS. Each video is
classified with the app's own pipeline and confirmation rule:
frames at the middles of CONFIRM_VERDICTS equal segments, the most
confident face cropped and sent to BitMind, a first REAL verdict
final, otherwise more verdicts until verdict_decided(). Each video's
verdicts are appended to results/accuracy_results.csv as soon as it
finishes, so an interrupted run resumes. The summary (also written
to results/accuracy_summary.txt) compares a single verdict with the
confirmed verdict (confusion counts, accuracy, balanced accuracy,
precision, recall, F1, false-positive rate), lists per-method
results with ROC-AUC, and sweeps thresholds 0.5-0.9.
--summary-only re-prints it from the CSV without API calls.

----------------------------------------------------------------
20. realtime_performance.py
----------------------------------------------------------------
Test script measuring real-time performance. It plays
PERF_VIDEOS_PER_SUBSET FaceForensics++ clips per subset in real
time, letterboxed to the primary screen's resolution with a short
black gap between clips, through a copy of DetectionWorker's
architecture: a main loop at DISPLAY_FPS (a real screen grab every
tick for its cost, face detection on the clip frame, tracking and
queueing) and a round-robin BitMind thread with the same
confirmation rule. After a PERF_WARMUP_SECONDS warm-up it records
per-tick latency split by stage, FPS, the app process's CPU (the
simulated player's decoding excluded) and RAM, and per clip the
time from a face first being tracked to its first and final
verdict. Results are compared with the TARGET_* values in config.py
(PASS/FAIL) and saved to results/performance_summary_<time>.txt,
with per-clip rows in results/performance_videos_<time>.csv.
It also holds the test lock (_hold_test_lock, results/.test.lock)
that all three test scripts take at start: a test started while
another is running exits at once, because concurrent tests compete
for the screen, the CPU and BitMind's per-key rate limit.

----------------------------------------------------------------
21. screen_face_pipeline.py
----------------------------------------------------------------
Test script for the screen capture -> face crop -> face tracking
workflow, up to the JPEG the app submits to BitMind. BitMind is not
called (API speed and accuracy are covered by realtime_performance.py
and detection_accuracy.py), so no API key or network is needed. A
separate player process (standing in for the video-call app) shows
PIPELINE_VIDEOS_PER_SUBSET FaceForensics++ clips per subset full
screen on the primary monitor, with black gaps between clips, and
publishes which clip is on screen and when it appeared. The pipeline
grabs the real screen with mss at DISPLAY_FPS, runs MediaPipe
detection and cropping on the grab, tracks the faces, and prepares
every face's 224x224 JPEG payload (an upper bound: the app prepares
one per second). After a PERF_WARMUP_SECONDS warm-up it reports FPS,
screen-grab, detect + crop, tracking and payload-preparation times,
JPEG size, the face hit rate on clip frames, false detections on
black gap frames, main-face track continuity, frame latency (grab ->
payloads ready) and the time from a face appearing on screen to its
first payload, compared with the TARGET_* values in config.py
(PASS/FAIL). Results are saved to results/pipeline_summary_<time>.txt,
per-clip rows to results/pipeline_clips_<time>.csv, and the first
JPEG of each face track to results/pipeline_crops_<time>/. Esc in the
video window stops the run early.
